# AstroCare Testing Guide

This guide describes how to author tests, register test suites, utilize offline mock providers, and interpret results generated by the AstroCare Quality Assurance Framework.

---

## 1. Test Categories

The test orchestrator categorizes tests into 13 formal verification classifications:

| Category | Description | Primary Validator / Service |
| :--- | :--- | :--- |
| `BIOMEDICAL` | Physiological limits, unit consistency, spike/rate-of-change, data schemas | `BiomedicalValidator` |
| `SCIENTIFIC` | Mathematical precision, Z-scores, percentage deviation invariants, radiation dosimetry | `CalculationValidator`, `RadiationCalculator` |
| `AI_GROUNDING`| Gemini response verification, anti-hallucination, deterministic fallback | `AIResponseValidator`, `MockGeminiProvider` |
| `NASA_DATA` | Authority sources: `api.nasa.gov`, OSDR, NTRS citations, Data Portal | `NasaApiAdapter`, `NasaOsdrAdapter`, etc. |
| `SECURITY` | Regex secret scanning, environment audits, XSS and injection defense | `SecretScanner`, `SecurityAuditor` |
| `PERFORMANCE` | High-volume batch ingestion (10k items), latency budgets, moving averages | `PerformanceBenchmarker` |
| `REGRESSION` | Module manifests, duplicate routes, service collision, dependency graphs | `ModuleCompatibilityValidator` |
| `ACCESSIBILITY`| WCAG 2.1 AA audits on mission interfaces via `axe-core` | JSDOM / React Testing Library |
| `INTEGRATION` | Inter-service contracts, orchestrator pipelines, dependency blocking | `AstroCareModuleRegistry` |
| `E2E` | 11-step clinical & aerospace decision-support user workflows | Reusable workflow adapters |
| `FUNCTIONAL` | General component and state verification | Standard runners |
| `UNIT` | Granular function-level tests | Vitest |
| `API` | HTTP status codes, pagination, timeouts, retry policies | `ApiTestClient` |

## 2. Test Execution Statuses

The framework distinguishes between test failures and unexecutable tests:

- **`PASS`**: The test executed and all assertions passed.
- **`FAIL`**: The test executed but encountered an assertion failure or uncaught exception.
- **`BLOCKED`**: The test was **not allowed to execute** because a prerequisite dependency test (`dependsOn`) failed or was not executed.
- **`WARNING`**: The test passed structural assertions but flagged operational threshold issues (e.g., physiological rate-of-change spikes).
- **`SKIPPED`**: The test was intentionally bypassed (e.g., live network tests during offline runs).

## 3. How to Add a New Test

To add a new test case into a suite:

```typescript
import { TestOrchestrator, BiomedicalValidator } from '@astrocare/qa-framework';

const orchestrator = new TestOrchestrator();

orchestrator.registerSuite({
  id: 'suite-eva-metabolic',
  name: 'EVA Metabolic Rate Verification',
  moduleName: 'Spaceflight Environmental Monitoring',
  category: 'BIOMEDICAL',
  description: 'Validates oxygen consumption rate during extravehicular activity.',
  tests: [
    {
      id: 'eva-met-001',
      name: 'Oxygen Uptake Nominal Invariant',
      category: 'BIOMEDICAL',
      moduleName: 'Spaceflight Environmental Monitoring',
      description: 'Checks VO2 consumption during lunar surface egress.',
      severity: 'HIGH',
      dependsOn: [], // Optional prerequisite test IDs
      timeoutMs: 5000,
      fn: async () => {
        const validator = new BiomedicalValidator();
        const telemetry = {
          recordId: 'REC-EVA-01',
          astronautId: 'ASTRO-CDR-01',
          missionId: 'MISSION-ARTEMIS-III',
          timestamp: new Date().toISOString(),
          metricType: 'oxygen_saturation' as const,
          value: 97,
          unit: '%' as const,
          sourceDevice: 'Suit-LifeSupport-O2',
        };

        const result = validator.validate(telemetry);
        if (!result.isValid) {
          throw new Error(`Expected valid reading, got: ${result.schemaErrors[0].message}`);
        }
      },
    },
  ],
});

// Run registered suites
const report = await orchestrator.runAll();
console.log(`Passed: ${report.summary.passed}/${report.summary.totalTests}`);
```

## 4. How to Register an AstroCare Module

To audit an AstroCare module for integration readiness:

```typescript
import { ModuleCompatibilityValidator } from '@astrocare/qa-framework';

const validator = new ModuleCompatibilityValidator();

validator.registerModule({
  moduleId: 'astrocare-cardiovascular',
  moduleName: 'Cardiovascular Analytics Module',
  moduleVersion: '1.4.0',
  category: 'BIOMEDICAL',
  requiredServices: ['biomedical-vital-service'],
  providedServices: ['cardiac-arrhythmia-service'],
  exportedTypes: ['CardiovascularTelemetryRecord'],
  registeredRoutes: ['/analytics/cardiac'],
  dataContracts: [
    {
      contractId: 'contract-cardiac-v1',
      version: '1.0.0',
      schemaDefinition: 'CardiacTelemetrySchema',
      inputTypes: ['TelemetryRecord'],
      outputTypes: ['CardiacAssessmentResult'],
    },
  ],
});

const audit = validator.validateAll();
if (!audit.isCompatible) {
  console.error('Module integration blocked:', audit.missingDependencies);
}
```

## 5. How to Use Mock Providers

All adapters include fully offline, deterministic mock modes requiring zero internet access or API credentials:

```typescript
import { MockGeminiProvider, NasaApiAdapter, NasaOsdrAdapter } from '@astrocare/qa-framework';

// 1. Mock Gemini Provider
const gemini = new MockGeminiProvider({
  simulateFailureMode: 'NONE', // 'NETWORK_TIMEOUT', 'RATE_LIMIT', etc.
  deterministicFallbackEnabled: true,
});

// 2. NASA API Adapter in Mock Mode
const nasaApi = new NasaApiAdapter({ mockMode: true });
const connection = await nasaApi.verifyConnection();

// 3. NASA OSDR Adapter in Mock Mode
const osdr = new NasaOsdrAdapter(true);
const study = await osdr.getStudy('OSD-379');
```

## 6. Interpreting Test Reports

The test engine generates three exportable artifacts:

1. **JSON (`TestReportGenerator.toJSON(report)`)**: Full programmatic structure containing suite durations, individual test results, failure stack traces, and module health scores.
2. **Interactive HTML (`TestReportGenerator.toHTML(report)`)**: Self-contained, single-file HTML report with embedded responsive dark theme, KPI counters, module status cards, and expandable test details.
3. **CSV (`TestReportGenerator.toCSV(report)`)**: Tabular export ready for spreadsheet analysis or flight safety review boards.
